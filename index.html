Four roles, one artifact trail

Keep each model in a separate Conductor workspace. Share committed branches, pull requests, explicit diff summaries, or `.context` notes so reviewers inspect the same evidence.

1

Builder workspace

Implements the change on its own branch and leaves a reviewable artifact: commit, pushed branch, PR, or clear `.context` handoff.

2

Adversarial reviewer

Reviews the branch against `origin/main` and leads with blocking bugs, missing tests, regressions, and flawed assumptions.

3

Specialist pass

Runs only when risk warrants it: security, auth, data, deploys, frontend quality, performance, money, or brand.

4

Synthesis agent

Compares reviews, removes noise, names the real blockers, and returns the exact next implementation move.

Operating rules

The value comes from independent judgment plus shared evidence. More agents only help when each one has a clear role.

Default cadence

  • Use one builder and one adversarial reviewer before merge.
  • Add a specialist only for high-risk or high-ambiguity work.
  • Have one synthesis agent decide which findings actually matter.

Evidence rule

  • Uncommitted work in another workspace is invisible by default.
  • Review committed branches, PRs, explicit diffs, or `.context` notes.
  • Ask reviewers for file and line references whenever possible.
